# ScopePay AI 2.2 Architecture

## Public visitor flow

1. `GET /api/auth/session` creates or resumes an anonymous visitor session.
2. The server stores a random visitor ID and CSRF token in a signed HttpOnly cookie-backed session.
3. All workspace API requests resolve the owner ID from the server-side session, never from request JSON.
4. A request-scoped store loads only rows matching that owner ID.
5. Mutations persist only the current owner's rows.

## PostgreSQL tables

- `scopepay_projects`
- `scopepay_analyses`
- `scopepay_negotiations`
- `scopepay_change_orders`
- `scopepay_activities`
- `scopepay_visitors`
- `scopepay_credentials`
- `scopepay_public_tokens`
- `scopepay_sessions`

Existing rows are preserved with `owner_id IS NULL`; public visitor sessions cannot load those records. New visitor IDs are generated by the server. All tenant queries filter by `owner_id`.

## Credentials

Gemini API keys and PayPal Sandbox Client ID/Secret values are encrypted with AES-256-GCM using `CREDENTIALS_ENCRYPTION_KEY`. Only the backend decrypts them for API calls. The key must remain stable across deployments. No integration secret is returned to the browser.

## Client links

Negotiation and payment links use high-entropy bearer tokens. The database stores only SHA-256 token hashes in `scopepay_public_tokens`, mapping a valid token to its owning workspace and target record. Public endpoints load only that workspace and only return the specific negotiation or change order.

## Payment handling

Each visitor's PayPal Sandbox credentials are used for that visitor's merchant operations. The client checkout receives the public PayPal Client ID for the specific order after token validation. Order amounts and currency are read from server-side records, and the backend verifies the completed capture before marking a change order paid.

## Local mode

Local development uses `TenantJsonStore` with a visitor data file beside the configured legacy JSON file. Express sessions are process-local in local mode. Production uses PostgreSQL-backed sessions.
